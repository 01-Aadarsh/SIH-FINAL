Why Standard RAG Fails Here

A typical chatbot pipeline:

Embed Query
→
Top-20 Similar Chunks
→
Feed to LLM
→
Answer (+ Made-Up Citations)

Three gaps that let hallucinations slip through:

1. Semantic-only retrieval: Dense embeddings catch "similar meaning" but miss exact section numbers and statutory terms the law actually uses.
2. No ranking: You get 20 chunks; some are on-topic, some are noise. You feed all of them to the LLM and hope it picks the right ones.
3. Model-Written Citations: The LLM invents page numbers and section titles that sound real but never existed. You can't audit what it read.

Our Architecture: 4 Design Decisions

1. Hybrid Retrieval (BM25 + Dense, Fused by RRF)
BM25 finds exact section numbers and statutory terms (rules that read "Section 3(p) excludes traditional knowledge" will always match the query "section 3(p)"). Dense embeddings find semantic similarity. Reciprocal Rank Fusion merges both signals — a chunk that ranks well on BOTH rises to the top.
2. Cross-Encoder Reranking
After fusing to top 20, a cross-encoder re-reads each (query, chunk) pair together and assigns a calibrated confidence score [0,1]. Keeps only the top 5 most relevant chunks. Empirical: on-topic queries score 0.92–0.999; genuinely out-of-scope queries score ~0.000.
3. Programmatic Citations (The Core Insight)
The LLM never writes a citation. Our code tracks which chunks were retrieved, extracts their source_file, page_number, and section_heading, and attaches those as the source list. A citation cannot be hallucinated if the model never generates it.
4. Abstention Guardrail
If retrieved context doesn't contain the answer, the system responds "I could not find this in my sources" and asks one clarifying question instead of guessing. This is the only truthful response when out-of-scope.

Real Challenges We Solved

Challenge: Windows Event Loop Crashes Psycopg Async
How we solved it: Set asyncio event loop policy before importing anything. Bundled into run.py launcher so developers don't need to think about it. Same code runs on Mac/Linux without modification.
Challenge: BM25 Tokenizer Must Match at Query & Index Time
How we solved it: Centralized tokenizer with domain synonyms (trademark ↔ trade mark, IPR ↔ intellectual property rights, TK ↔ traditional knowledge). Single shared function imported everywhere, no drift.
Challenge: Groq API Daily Token Quota Exhaustion
How we solved it: Multi-key rotation. GROQ_API_KEY_2, GROQ_API_KEY_3, ... are tried automatically on a 429 (quota hit). Discovered this was a real problem during benchmark runs; now it's transparent to callers.
Challenge: Clause-Level Chunks Break RRF Top-20 Cutoff
How we solved it: Raised FUSED_TOP_K from 20 to 40. Caught by regression test for a known query (Section 3(p)) that worked before the hierarchical chunker but broke after. Fixed, verified, tested.
